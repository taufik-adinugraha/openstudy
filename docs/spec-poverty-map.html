Phase 3 · Case F · Spec v1

Poverty Mapping from Space

Rooftops, lights, land cover and roads as welfare signals — a gradient-boosted small-area model trained on BPS's official regency poverty rates (2016–2025), spatially cross-validated, then carried down to the kecamatan and benchmarked so the official number is never contradicted.

F1 · The question

“Which neighbourhoods are poor — in the three-year gap between surveys, and below the level any survey reaches?”

BPS publishes poverty for 514 kabupaten/kota once a year; nothing official exists below that. Yet the welfare signal is sitting overhead: how many buildings, how big their roofs, how bright the night, how far the paved road. This case proves the geo-ML capability — train against every official rate 2016–2025, validate out-of-province and out-of-year, then hand a client a kecamatan-level map with honest intervals. The framing matters: the model distributes the official number within a regency; it never replaces it. DHS/Susenas microdata are restricted, and that constraint is disclosed, not hidden.

Scope rule (load-bearing): the target is the BPS poverty rate (P0, % below the official line) — never asset wealth, never consumption. Every map states the year and the survey it distributes. Kecamatan values are model estimates benchmarked to the official regency rate; the word “estimate” and the interval appear wherever they do.

F3 · Pipeline

Pipeline — static rebuild (SCOPE=java fast path · idn full)

~20 GB through the pipe nationally (~11 GB Java-only), dominated by Open Buildings; run once, keep reduced grids. Estimated wall time on the 16 GB dev server: ingest 3–5 h (bandwidth-bound), features ~1–2 h (DuckDB + exactextract, windowed), train/downscale minutes. Fits in < 8 GB RAM via streaming + COG windows.

ingest

BPS P0/P1/P2/line 2016–2025 (one request per var × year, browser UA); COD-AB gdb + P-code xlsx; Open Buildings cells (level-6 partitions, streamed → 100 m counts/areas/size-histogram grid → csv.gz deleted); WorldPop R2025A 2016–2025; WorldCover tiles; GHSL BUILT-S/NRES/SMOD; OSM highways; Black Marble annuals reused from Flagship A. Manifest with sizes + sha256.

features

One 100 m analysis grid → identical aggregation to ADM2 (519/522) and ADM3 (7,069): building density, footprint share, median/p90 roof size, share < 40 m², lights mean/sum-per-capita/lit-share/trend, WorldCover shares, built-up + non-residential per capita, SMOD class shares, road density by class, population-weighted distance to primary road. Same code path both levels — no train/serve skew.

train

LightGBM (+ ridge baseline for honesty) on regency P0. CV is spatial: leave-one-province-out (34 folds) headline, 200 km block k-fold sensitivity, random k-fold computed only to show how much it flatters. SHAP per regency for the drilldown.

downscale

Apply to kecamatan features → benchmark: population-weighted mean per regency equals the official rate, exactly. Intervals: LightGBM quantile p10/p90 widened by the province's CV residual.

validate

Gates G-F1…G-F4 below → stats.json.

export

View-models ≤ 3 MB each (NaN-safe): ADM2/ADM3 GeoJSON, ledger (BPS series + prediction + SHAP top-5), estimates with intervals, skill panel (Java/off-Java, spatial-vs-random CV). Insight brief per D11.

F4 · Validation gates

Validation gates

Thresholds anchored to the literature: Jean 2016 (R² 0.55–0.75, asset wealth), Yeh 2020 (R² ≈ 0.70 villages), Chi 2022 (spatial-CV R² 0.56), and for Indonesia specifically Putri 2022 (East Java: Pearson 0.71, Spearman 0.77, RMSE 3.2 pp vs BPS) and Sartirano 2023 (Spearman 0.75 across 513 regencies).

G-F1 — Out-of-sample skill (hard). Leave-one-province-out on the latest year's cross-section: R² ≥ 0.50, Spearman ρ ≥ 0.70, RMSE ≤ 4.0 pp. Below any of these, the case does not ship.
G-F2 — Java / off-Java disclosure. Both R² published side by side. If off-Java R² < 0.35, every off-Java estimate is labelled “indicative” and its interval widened accordingly. Urban (kota) vs rural (kabupaten) skill shown the same way.
G-F3 — Temporal hold-out. Train ≤ 2023, predict the 2024 and 2025 BPS releases: Spearman ρ ≥ 0.65 each — the “sees forward, not just sideways” test a client will ask about.
G-F4 — Benchmark integrity (hard). After benchmarking, population-weighted kecamatan estimates reproduce every regency's official rate within 0.1 pp. Bookkeeping — must be exact.
F5 · Dashboard

Dashboard — page anatomy

Map rule for the whole case: the user's own browser runs with WebGL off, so every map ships with a full-function 2-D canvas fallback (Path2D + isPointInPath hit-testing, the pattern proven in cases/nightlights-pulse/web) — try MapLibre, catch, degrade with a visible “2-D MAP” tag.

  1. Hero — “What the satellite knows.” Signature moment: a single kampung block rendered as its raw ingredients — footprints fading in one layer at a time (roofs → lights → roads → land cover) — then the layers collapse into one ochre poverty surface. 2-D fallback: the same sequence pre-composited as crossfading static canvases. Reduced motion: final frame.
  2. Chapter 1 — “The official map, and its resolution.” BPS regency choropleth 2016–2025 with a year scrubber — the truth the model must respect, and its coarseness as the motivation.
  3. Chapter 2 — “How well it predicts.” The trust chapter, up front: model-vs-BPS scatter (each dot a regency, hover for name/values), spatial-vs-random CV comparison, Java vs off-Java split, temporal hold-out result. All gates rendered with their thresholds.
  4. Chapter 3 — “What the model looks at.” SHAP feature-family bars; a regency drilldown showing its top-5 contributions in plain words (“small roofs and dim nights pull this one up”).
  5. Chapter 4 — “Below the survey line.” The payoff: kecamatan estimates inside their regencies, intervals visible, benchmark factor disclosed; “most confident contrasts” list (kecamatan pairs in one regency with non-overlapping intervals).
  6. Explore. Choropleth (ADM2 ↔ ADM3 toggle, year scrubber, P0/P1/P2 metric switch); click → panel (official vs estimate, interval, SHAP top-5, population); URL state; chart/table toggle + data download per Grapher affordances.
  7. Methodology. The restricted-microdata disclosure; benchmarking math; CV design; every licence and attribution (BPS, Google Open Buildings CC BY 4.0, Microsoft CDLA, NASA, WorldPop, ESA WorldCover line, GHSL, OSM ODbL, COD-AB CC BY-IGO); rejected-layers note (RWI CC BY-NC et al.).

F6 · Design brief

Design brief

Identity: ground truth — rooftops and soil. Dark humus ground, ochre accent; the poverty ramp runs soil-dark → ochre → pale sand so “brighter = poorer” never happens (lights are a feature, not the message). BPS official series always in the site-wide provenance teal; model estimates in ochre — the two are never the same hue.

  • Numbers carry year + provenance: “12.4 % · BPS 2025” vs “9.1 % (7.3–11.2) · model estimate”.

F8 · Risks & decisions pending

Risks, unknowns & decisions pending user verification

  • Open Buildings volume vs the 16 GB box — cell 2e7 alone is 5.9 GB gz; mitigated by the level-6 partition + streaming reduction; the fallback is Microsoft footprints (4.7 GB, CDLA-Permissive).
  • Feature vintages straddle the panel — WorldCover is 2021-only, Open Buildings ~2023, GHSL 2020 epochs; annual variation is carried by lights + WorldPop only. Disclosed; the model is primarily a spatial disaggregator.
  • 522 vs 514/519 ADM2 units — COD-AB (522) vs BPS publication (514) vs geoBoundaries (519); reconciled through P-codes + the flagship's pemekaran crosswalk before training.
  • Ecological fallacy at ADM3 — a regency model applied to kecamatan features; the benchmark + intervals are the mitigation, and the methodology says so in plain words.
  • Pending user verification: (1) accept the CC BY-4.0 election for Open Buildings and drop of RWI/SMERU (both CC BY-NC) — this removed the planned independent wealth cross-check; (2) COD-AB as the ADM3 topology instead of geoBoundaries (which lacks ADM3); (3) Kemendesa IDM as an optional village-level check once its licence is clarified; (4) whether an annual re-run (each March release) is worth a cron slot vs D3's static rule.
  • Out of scope: individual/household targeting, consumption prediction, embedding models (Tessera/Major TOM — v2), Podes purchase.
